1. Profil Aplikasi & Arsitektur Sistem

1.1 Deskripsi Singkat Aplikasi

TaskFlow adalah sistem aplikasi manajemen tugas (To-Do List) dan ruang kerja produktivitas (productivity workspace) yang dirancang untuk membantu siswa, guru, maupun profesional dalam menyusun target kerja secara terstruktur. Aplikasi ini tidak hanya menyediakan fungsi dasar CRUD (Create, Read, Update, Delete) tugas, tetapi juga dilengkapi dengan sub-tugas checklist bertingkat, jadwal kegiatan mingguan, papan catatan bebas (sticky notes) dengan upload gambar, timer fokus (Teknik Pomodoro), metrik analisis penyelesaian tugas, serta laporan fisik cetak (Printable Report) yang siap dicetak untuk arsip dokumen.

1.2 Arsitektur Sistem: Decoupled Fullstack

Aplikasi dibangun dengan konsep Decoupled Architecture (Frontend dan Backend terpisah 100%), yang merupakan standar industri perangkat lunak modern:

Komponen Teknologi Alamat (Port) Tanggung Jawab Utama
Backend API Laravel 11 + Sanctum http://127.0.0.1:8000 Menyediakan endpoint RESTful JSON, validasi data FormRequest, relasi database Eloquent ORM, dan keamanan token.
Frontend SPA React 19 + Vite + Tailwind http://127.0.0.1:5173 Merender antarmuka pengguna interaktif (SPA), animasi modal, kalkulasi status real-time, audio feedback, dan print preview.
Database Server MySQL (Laragon/XAMPP) 127.0.0.1:3306 Menyimpan tabel user, tasks, subtasks, sticky_notes, schedules, dan personal_access_tokens.
Launcher Orkestrasi Node.js (start.js) Terminal CLI / run.bat Mengecek koneksi MySQL, auto-create database db_taskflow, migrate tabel, lalu menyalakan Laravel & Vite bersamaan.
Keunggulan Arsitektur Decoupled saat Dinilai Penguji UKK:
  • Modular & Reusable: Endpoint API backend yang dibuat di Laravel dapat digunakan oleh aplikasi lain (seperti aplikasi Android/Flutter) tanpa mengubah backend.
  • Performa Tinggi (SPA): Pergantian halaman di frontend berlangsung instan tanpa reload browser, memberikan pengalaman pengguna (UX) yang sangat mulus.
  • Pemisahan Tugas Jelas: Logika bisnis dan keamanan data berada ketat di sisi server (Backend), sementara urusan visual dan interaktivitas berada di sisi klien (Frontend).

2. Letak Link & Konfigurasi Koneksi Database

PENTING: Pertanyaan Wajib Penguji UKK!
"Di mana pengaturan koneksi databasenya? Bagaimana cara aplikasi terhubung ke MySQL?"
Berikut adalah jawaban tepat dan file-file yang wajib Anda tunjukkan kepada dewan penguji.

2.1 File Utama: backend/.env

File lingkungan (environment variables) ini merupakan lokasi utama di mana konfigurasi kredensial MySQL disimpan. Laravel membaca file ini setiap kali aplikasi memproses permintaan database. 

# Konfigurasi Koneksi Database MySQL (backend/.env)
DB_CONNECTION=mysql          # Driver database yang digunakan
DB_HOST=127.0.0.1            # Alamat host server MySQL lokal (localhost)
DB_PORT=3306                 # Port default MySQL di Laragon / XAMPP
DB_DATABASE=db_taskflow      # Nama database yang digunakan aplikasi
DB_USERNAME=root             # Username default MySQL di Laragon/XAMPP
DB_PASSWORD=                 # Password default (biasanya kosong di lokal)

2.2 File Pendukung: backend/config/database.php

File konfigurasi internal framework Laravel yang mendefinisikan array driver koneksi 'mysql'. File ini mengambil nilai dinamis dari file .env menggunakan fungsi pembantu env(): 

'mysql' => [
    'driver'    => 'mysql',
    'host'      => env('DB_HOST', '127.0.0.1'),
    'port'      => env('DB_PORT', '3306'),
    'database'  => env('DB_DATABASE', 'forge'),
    'username'  => env('DB_USERNAME', 'forge'),
    'password'  => env('DB_PASSWORD', ''),
    'charset'   => 'utf8mb4',
    'collation' => 'utf8mb4_unicode_ci',
    'prefix'    => '',
    'strict'    => true,
    'engine'    => null,
],

2.3 Otomatisasi Database di start.js (Inovasi Nilai Tambah UKK)

Dalam proyek ini, terdapat inovasi pada file start.js (baris 109–165). Saat Anda mengklik run.bat atau mengetik npm run dev:

  1. Skrip Node.js melakukan socket ping ke 127.0.0.1:3306 untuk mengecek apakah MySQL sudah dinyalakan di Laragon/XAMPP.
  2. Jika database db_taskflow belum ada di phpMyAdmin, skrip otomatis menjalankan perintah PDO PHP:
    CREATE DATABASE IF NOT EXISTS `db_taskflow` CHARACTER SET utf8mb4 ...
  3. Menjalankan php artisan migrate --force secara otomatis untuk membuat seluruh tabel tanpa perlu mengetik manual di terminal!

2.4 Menghubungkan Frontend ke Backend (Proxy API)

Agar Frontend React dapat berkomunikasi dengan Backend Laravel tanpa terhalang kendala CORS (Cross-Origin Resource Sharing):

  • frontend/vite.config.js: Diberi konfigurasi server.proxy yang meneruskan setiap permintaan berawalan /api ke target http://127.0.0.1:8000.
  • frontend/src/api/axiosClient.js: Dibuat instance Axios dengan baseURL: '/api' serta request interceptor yang otomatis menyisipkan header:
    Authorization: Bearer <token_sanctum> dari localStorage.

3. Skema Tabel Database & Relasi (ERD)

Aplikasi TaskFlow memiliki 6 tabel utama yang dibuat menggunakan fitur Laravel Database Migrations (tersimpan di folder backend/database/migrations/):

Nama Tabel Kolom Utama Relasi (Foreign Key) Keterangan & Perilaku
users id, name, email, password, avatar_url Induk (Parent) Menyimpan akun pengguna. Password di-hash menggunakan algoritma bcrypt.
tasks id, user_id, title, description, status, priority, category, due_date, is_pinned user_id → users.id (Cascade Delete) Menyimpan entitas tugas. Jika user dihapus, seluruh tugasnya otomatis terhapus.
subtasks id, task_id, title, is_completed task_id → tasks.id (Cascade Delete) Daftar checklist langkah pengerjaan tugas. Menghitung persentase progres tugas secara otomatis.
schedules id, user_id, title, location, category, date, start_time, end_time, color, status user_id → users.id (Cascade Delete) Agenda jadwal kegiatan mingguan siswa/pengguna untuk dipetakan ke timeline kalender.
sticky_notes id, user_id, title, content, color, pos_x, pos_y, image user_id → users.id (Cascade Delete) Papan catatan tempel interaktif dengan koordinat drag-and-drop dan lampiran gambar.
personal_access_tokens id, tokenable_id, name, token, abilities, last_used_at Polymorphic Sanctum Tabel resmi Laravel Sanctum untuk mencatat token sesi login pengguna yang aktif.

Penjelasan Konsep Cascade on Delete:
Jika penguji bertanya: "Apa yang terjadi pada sub-tugas jika tugas utamanya dihapus?"
Jawab: "Karena menggunakan $table->foreignId('task_id')->constrained('tasks')->cascadeOnDelete(); pada file migrasi, maka seluruh sub-tugas yang terhubung akan otomatis terhapus dari MySQL demi menjaga integritas data (tidak ada data yatim/orphan record)."

6. Alur Kerja Sistem & Mekanisme Keamanan

6.1 Alur Autentikasi Pengguna (Login & Sesi)

[Pengguna]
   |
   | 1. Memasukkan Email & Password
   v
[Frontend React: AuthPage]
   |
   | 2. POST /api/login via Axios
   v
[Backend Laravel: AuthController@login]
   |
   | 3. Validasi FormRequest & Verifikasi Password (Hash::check)
   | 4. Generate Token Sanctum: $user->createToken('taskflow_auth')
   v
[Database MySQL: personal_access_tokens] (Token disimpan)
   |
   | 5. Return JSON: { token: "1|xyz...", user: {...} }
   v
[Frontend React: AuthContext]
   |
   | 6. Simpan token & user di localStorage ('taskflow_token')
   | 7. Update state: isAuthenticated = true
   v
[Halaman Dashboard Terbuka!]

6.2 Mekanisme Keamanan yang Diterapkan (Nilai Tambah UKK)

  1. Enkripsi Password (Bcrypt): Password pengguna tidak pernah disimpan dalam bentuk teks biasa (plain text), melainkan dienkripsi dengan algoritma bcrypt (12 round salt).
  2. Token-based Authentication (Laravel Sanctum): Setiap request ke rute data pribadi wajib menyertakan token otentikasi. Token ini di-hash dengan aman di tabel personal_access_tokens.
  3. Proteksi SQL Injection (Eloquent ORM & PDO): Seluruh query database menggunakan parameter binding otomatis dari PDO dan Eloquent, sehingga kebal terhadap serangan injeksi SQL klasik.
  4. Proteksi Mass Assignment: Atribut model dilindungi dengan $fillable, sehingga penyerang tidak dapat mengubah data kolom sensitif (seperti id user atau hak akses) secara ilegal.
  5. Data Isolation (Multi-tenant Sederhana): Setiap query tugas, jadwal, dan catatan difilter ketat berdasarkan user yang sedang login (auth()->id()). Pengguna A tidak dapat melihat atau mengubah tugas Pengguna B.
  6. Validasi Input Ketat (FormRequest): Data yang masuk divalidasi tipe data, batas karakter, dan keharusannya sebelum diproses oleh database.

7. Kisi-kisi Pertanyaan Penguji UKK & Kunci Jawaban

Q1: "Mengapa kamu memilih arsitektur terpisah (React dan Laravel) daripada Blade bawaan Laravel?"
Jawaban: Karena arsitektur terpisah (Decoupled) adalah standar industri modern. Dengan membuat backend murni sebagai RESTful API, backend ini bersifat reusable (dapat dipakai oleh aplikasi mobile Android/iOS di masa depan). Selain itu, frontend React bekerja sebagai Single Page Application (SPA) yang tidak memerlukan refresh halaman saat navigasi, sehingga aplikasi terasa jauh lebih responsif dan hemat kuota data.
Q2: "Di mana letak file koneksi database dan apa nama databasenya?"
Jawaban: File utama berada di backend/.env pada variabel DB_DATABASE=db_taskflow, DB_HOST=127.0.0.1, dan DB_PORT=3306. File ini dibaca oleh konfigurasi framework di backend/config/database.php. Selain itu, pada file launcher start.js, terdapat skrip otomatis yang mendeteksi koneksi MySQL dan membuat database tersebut jika belum ada.
Q3: "Bagaimana cara kerja autentikasi dan penyimpanan sesi login pengguna?"
Jawaban: Menggunakan Laravel Sanctum. Ketika login berhasil di AuthController@login, server membuat token akses unik. Token tersebut dikirim ke frontend React dan disimpan di localStorage. Setiap kali React melakukan request data (CRUD), axiosClient.js secara otomatis menyisipkan token tersebut pada header Authorization: Bearer <token>.
Q4: "Bagaimana relasi antara tabel Tasks dan Subtasks di database?"
Jawaban: Relasinya adalah One-to-Many (Satu tugas dapat memiliki banyak sub-tugas checklist). Relasi ini diatur melalui foreign key task_id pada tabel subtasks yang merujuk ke tasks.id dengan aturan cascadeOnDelete(). Di model Laravel, dihubungkan dengan public function subtasks() { return $this->hasMany(Subtask::class); }.
Q5: "Apa arti HTTP Status Code 200, 201, 401, 422, dan 500?"
Jawaban:
  • 200 OK: Permintaan berhasil diproses (misal: mengambil data tugas).
  • 201 Created: Data baru berhasil dibuat di database (misal: tambah tugas baru).
  • 401 Unauthorized: Sesi habis atau token login tidak valid.
  • 422 Unprocessable Entity: Validasi form gagal (misal: judul tugas kosong).
  • 500 Internal Server Error: Terjadi kesalahan logika di sisi server/backend.
Q6: "Bagaimana cara kerja fitur Cetak Laporan di aplikasi ini?"
Jawaban: Menggunakan komponen PrintableReport.jsx. Komponen ini merender data tugas dalam tata letak cetak resmi dan memanggil fungsi native browser window.print(). Diberikan styling khusus @media print yang menyembunyikan sidebar dan tombol antarmuka, sehingga hasil cetak bersih berformat A4 siap simpan ke PDF.
